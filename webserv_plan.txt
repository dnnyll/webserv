
================================================================================
                PLAN DE DÉVELOPPEMENT COMPLET - WEBSERV 42
================================================================================

Objectif général :
Créer un serveur HTTP non-bloquant capable de :
- gérer plusieurs clients simultanément,
- servir des fichiers statiques,
- gérer GET / POST / DELETE,
- exécuter des CGI,
- utiliser poll() (ou équivalent),
- parser un fichier de configuration type nginx.

Architecture recommandée :
- séparation claire des modules,
- machine d’état pour chaque client,
- boucle événementielle unique,
- aucune opération bloquante.

================================================================================
PHASE 1 : PARSING ET VALIDATION DE LA CONFIGURATION
================================================================================

Objectif :
Transformer le fichier de configuration en structures internes exploitables.

--------------------------------------------------------------------------------
1.1 Structures de données internes
--------------------------------------------------------------------------------

1.1.1 Structure "LocationConfig"

Doit contenir :

- chemin URI :
    /
    /images
    /cgi-bin

- méthodes autorisées :
    GET
    POST
    DELETE

- root spécifique

- index spécifique

- autoindex :
    on / off

- upload directory

- redirection :
    code HTTP
    URL destination

- extensions CGI :
    .py
    .php
    etc.

- flags d’héritage :
    hasRoot
    hasIndex
    etc.

--------------------------------------------------------------------------------
1.1.2 Structure "ServerConfig"
--------------------------------------------------------------------------------

Doit contenir :

- ports d’écoute

- server_name

- root par défaut

- index par défaut

- error pages :
    404 -> /errors/404.html

- client_max_body_size

- liste des LocationConfig

--------------------------------------------------------------------------------
1.1.3 Structure "ResolvedLocation"
--------------------------------------------------------------------------------

Objectif :
fusionner :
- configuration serveur
- configuration location

pour produire une configuration finale utilisable.

Permet :
- héritage propre,
- moins de duplication,
- comportement cohérent.

--------------------------------------------------------------------------------
1.2 Parsing du fichier
--------------------------------------------------------------------------------

1.2.1 Lecture du fichier

- open()
- read()
- fermeture propre
- gestion erreurs

--------------------------------------------------------------------------------
1.2.2 Tokenisation
--------------------------------------------------------------------------------

Découper :
- directives
- accolades
- valeurs
- blocs server
- blocs location

Exemple :

server {
    listen 8080;
}

--------------------------------------------------------------------------------
1.2.3 Parsing des blocs server
--------------------------------------------------------------------------------

Pour chaque bloc :

- créer ServerConfig
- parser directives
- parser locations

--------------------------------------------------------------------------------
1.2.4 Parsing des blocs location
--------------------------------------------------------------------------------

Pour chaque location :

- créer LocationConfig
- associer au serveur

--------------------------------------------------------------------------------
1.2.5 Validation syntaxique
--------------------------------------------------------------------------------

Vérifier :

- accolades valides
- directives connues
- arguments valides
- nombres valides
- ports valides
- méthodes valides
- autoindex on/off

--------------------------------------------------------------------------------
1.2.6 Validation sémantique
--------------------------------------------------------------------------------

Vérifier :

- ports uniques/cohérents
- chemins existants si nécessaire
- taille max > 0
- extensions CGI cohérentes

--------------------------------------------------------------------------------
1.2.7 Gestion des erreurs
--------------------------------------------------------------------------------

En cas d’erreur :

- afficher message explicite
- arrêter le programme

Exemples :

- directive inconnue
- accolade manquante
- port invalide
- mauvaise valeur

--------------------------------------------------------------------------------
1.2.8 Matching des locations
--------------------------------------------------------------------------------

IMPORTANT.

Le serveur doit choisir :
la location avec le plus long préfixe correspondant.

Exemple :

location /
location /images
location /images/icons

URI :
/images/icons/a.png

=> choisir :
/images/icons

Créer :

findBestLocation(uri)

--------------------------------------------------------------------------------
1.2.9 Résultat final
--------------------------------------------------------------------------------

Produire :

std::vector<ServerConfig>

prêt pour le module réseau.

================================================================================
PHASE 2 : COEUR RÉSEAU ASYNCHRONE
================================================================================

Objectif :
Gérer plusieurs connexions simultanément sans blocage.

--------------------------------------------------------------------------------
2.1 Initialisation des sockets
--------------------------------------------------------------------------------

Pour chaque port unique :

- socket()
- setsockopt(SO_REUSEADDR)
- fcntl(O_NONBLOCK)
- bind()
- listen()

--------------------------------------------------------------------------------
2.2 Structures réseau
--------------------------------------------------------------------------------

Conserver :

- sockets d’écoute
- mapping port -> serveurs
- clients connectés
- pollfd list

--------------------------------------------------------------------------------
2.3 Boucle événementielle
--------------------------------------------------------------------------------

Initialiser :

std::vector<pollfd>

Ajouter :
- sockets d’écoute
- sockets clients
- pipes CGI

Boucle infinie :

poll()

--------------------------------------------------------------------------------
2.4 Gestion des événements
--------------------------------------------------------------------------------

Si socket serveur :

- accept()
- O_NONBLOCK
- création client
- ajout pollfd

Si socket client :

- lecture
- écriture
- erreur
- fermeture

Si pipe CGI :

- lecture stdout CGI
- écriture stdin CGI

--------------------------------------------------------------------------------
2.5 Structure ClientConnection
--------------------------------------------------------------------------------

Doit contenir :

- fd socket
- read buffer
- write buffer
- état client
- timestamp activité
- requête en cours
- réponse en cours
- CGI éventuel
- serveur associé

--------------------------------------------------------------------------------
2.6 Machine d’état client
--------------------------------------------------------------------------------

IMPORTANT.

Créer :

enum ClientState
{
    READING_HEADERS,
    READING_BODY,
    PROCESSING,
    CGI_RUNNING,
    WRITING_RESPONSE,
    CLOSED
};

--------------------------------------------------------------------------------
2.7 Gestion lecture
--------------------------------------------------------------------------------

recv()

IMPORTANT :
une requête peut arriver en plusieurs morceaux.

Exemple :

"GET / HT"

puis :

"TP/1.1"

Le parsing doit être incrémental.

--------------------------------------------------------------------------------
2.8 Gestion écriture
--------------------------------------------------------------------------------

send()

IMPORTANT :
send() peut envoyer partiellement.

Retirer uniquement les octets réellement envoyés.

--------------------------------------------------------------------------------
2.9 Timeout clients
--------------------------------------------------------------------------------

IMPORTANT.

Éviter :
- clients morts
- slowloris
- fd bloqués

Ajouter :

lastActivity

Déconnecter après :
30-60 secondes d’inactivité.

--------------------------------------------------------------------------------
2.10 Gestion erreurs réseau
--------------------------------------------------------------------------------

Gérer :

- recv == 0
- recv == -1
- send == -1
- poll erreurs

Fermer proprement :
- socket
- buffers
- pollfd
- CGI éventuel

================================================================================
PHASE 3 : LOGIQUE HTTP
================================================================================

Objectif :
Transformer une requête HTTP en réponse HTTP.

--------------------------------------------------------------------------------
3.1 Parsing HTTP
--------------------------------------------------------------------------------

Créer :

HttpRequest

Contenant :

- méthode
- URI
- version HTTP
- headers
- body

--------------------------------------------------------------------------------
3.2 Parsing incrémental
--------------------------------------------------------------------------------

IMPORTANT.

Détecter :

fin headers :
\r\n\r\n

Puis :
- Content-Length
- chunked encoding

--------------------------------------------------------------------------------
3.3 Support Chunked Encoding
--------------------------------------------------------------------------------

Recommandé fortement.

Tester :

Transfer-Encoding: chunked

Sinon :
certains testeurs échouent.

--------------------------------------------------------------------------------
3.4 Sélection du serveur virtuel
--------------------------------------------------------------------------------

Quand plusieurs serveurs partagent un port :

server_name a.com
server_name b.com

Choisir via :

Header Host

--------------------------------------------------------------------------------
3.5 Résolution route
--------------------------------------------------------------------------------

- trouver meilleure location
- fusion serveur + location
- produire ResolvedLocation

--------------------------------------------------------------------------------
3.6 Validations HTTP
--------------------------------------------------------------------------------

Vérifier :

- méthode autorisée
- body size max
- URI valide
- permissions fichiers

--------------------------------------------------------------------------------
3.7 Traitement GET
--------------------------------------------------------------------------------

Construire chemin réel.

IMPORTANT :
sécuriser chemin.

Empêcher :

../../etc/passwd

Faire :
- normalisation chemin
- vérification root

--------------------------------------------------------------------------------
3.8 GET : dossier
--------------------------------------------------------------------------------

Si dossier :

- chercher index
- sinon autoindex

--------------------------------------------------------------------------------
3.9 Autoindex
--------------------------------------------------------------------------------

Si autoindex ON :

générer HTML dynamique :

- liste fichiers
- liens
- tailles éventuellement

--------------------------------------------------------------------------------
3.10 GET : fichier statique
--------------------------------------------------------------------------------

Lire fichier :

read()

Déterminer Content-Type.

Créer table MIME :

.html -> text/html
.css  -> text/css
.png  -> image/png
.js   -> application/javascript

--------------------------------------------------------------------------------
3.11 GET : CGI
--------------------------------------------------------------------------------

Si extension CGI :

déléguer Phase 4.

--------------------------------------------------------------------------------
3.12 POST
--------------------------------------------------------------------------------

Sauvegarder body :

- construire chemin upload
- write()

Retour :
201 Created

--------------------------------------------------------------------------------
3.13 DELETE
--------------------------------------------------------------------------------

unlink()
remove()

Retour :
204 No Content

--------------------------------------------------------------------------------
3.14 Construction réponse HTTP
--------------------------------------------------------------------------------

Créer :

HttpResponse

Construire :

- status line
- headers
- body

--------------------------------------------------------------------------------
3.15 Headers HTTP minimaux
--------------------------------------------------------------------------------

Ajouter :

- Content-Length
- Content-Type
- Date
- Connection
- Location (redirect)
- Server

--------------------------------------------------------------------------------
3.16 Pages d’erreurs
--------------------------------------------------------------------------------

Supporter :

200
201
204
301
302
400
403
404
405
413
500
501
504

Utiliser :
error_page si défini.

================================================================================
PHASE 4 : CGI
================================================================================

Objectif :
Exécuter scripts dynamiques sans bloquer le serveur.

--------------------------------------------------------------------------------
4.1 Détection CGI
--------------------------------------------------------------------------------

Si extension :
.py
.php
etc.

--------------------------------------------------------------------------------
4.2 Variables d’environnement
--------------------------------------------------------------------------------

Créer :

REQUEST_METHOD
QUERY_STRING
CONTENT_LENGTH
SCRIPT_FILENAME
PATH_INFO
SERVER_PROTOCOL
etc.

--------------------------------------------------------------------------------
4.3 Pipes CGI
--------------------------------------------------------------------------------

Créer :

pipe stdin CGI
pipe stdout CGI

--------------------------------------------------------------------------------
4.4 fork()
--------------------------------------------------------------------------------

Créer processus enfant.

--------------------------------------------------------------------------------
4.5 Processus enfant
--------------------------------------------------------------------------------

dup2()

rediriger :
- stdin
- stdout

Puis :

execve()

--------------------------------------------------------------------------------
4.6 Processus parent
--------------------------------------------------------------------------------

- pipes non bloquants
- ajout poll()
- suivi PID

--------------------------------------------------------------------------------
4.7 Communication CGI asynchrone
--------------------------------------------------------------------------------

poll() surveille :

- écriture stdin CGI
- lecture stdout CGI

--------------------------------------------------------------------------------
4.8 Timeout CGI
--------------------------------------------------------------------------------

IMPORTANT.

Si CGI boucle infiniment :

kill process.

Timeout :
5-10 secondes.

--------------------------------------------------------------------------------
4.9 Nettoyage CGI
--------------------------------------------------------------------------------

waitpid(WNOHANG)

Éviter zombies.

Fermer :
- pipes
- PID
- buffers
