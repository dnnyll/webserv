poll:
    poll(fds, nfds, timeout);


struct pollfd
{
    int   fd;         /* file descriptor */
    short events;     /* requested events */
    short revents;    /* returned events */
};


struct Client
{
    int fd;
    std::string read_buffer;
    std::string write_buffer;
};

std::vector<pollfd> poll_fds;
std::unordered_map<int, Client> clients;

EVENT LOOP FLOW
================

poll(pfds.data(), pfds.size(), timeout)
          |
          v

kernel modifies:
    pfds[i].revents

Example:
    pfds[1].revents = POLLIN

Meaning:
    fd 5 became readable


Your loop:
------------

for each pollfd in pfds
{
    if (p.revents & POLLIN)
    {
        int fd = p.fd;

        Client& c = clients[fd];

        read(fd, ...);

        append data into:
            c.read_buffer
    }
}


IMPORTANT IDEA
================

pollfd:
    only stores socket state information

Client:
    stores your application/protocol state

The fd connects both worlds.


KERNEL SIDE
============

socket fd 5
    |
    +-- incoming TCP data

poll():
    "fd 5 is readable"

Your server:
    "ok, get Client associated with fd 5"



When we call poll(fds, nfds, timeout) the kernel checks each fd:

"is socket readable?"
"is socket writable?"
"did it disconnect?"
"is there an error?"

then it fills fds[i].revents
