2. LA BOUCLE INFINIE POLL (DANS LE SERVERMANAGER)
=============================================================================

[ DÉPART ] ---> Le ServerManager lance sa boucle while(true)

      +-------------------------------------------------------------+
      |  poll() s'endort avec sa liste de FD (le panneau de bord).  |
      |  Il attend un événement réseau.                             |
      +-------------------------------------------------------------+
                                     |
    Un client se connecte ! (BOUM)   |   Ou un client parle ! (BOUM)
         (FD = 4 s'agite)            |        (FD = 5 s'agite)
                                     v

                        ServerManager regarde ses maps :
                        "À qui appartient ce FD qui clignote ?"
                                     |
             +-----------------------+-----------------------+
             |                                               |
             v                                               v
    [ C'EST DANS LA MAP SERVER ]                  [ C'EST DANS LA MAP CLIENT ]
    Le FD 4 appartient à un Server.               Le FD 5 appartient à un Client.
    C'est donc un tout NOUVEAU client !           C'est une suite de conversation !
             |                                               |
             v                                               v
    +------------------------------+              +------------------------------+
    | ACTION DU SERVER (Le Portier)|              | ACTION DU CLIENT (À table)   |
    |                              |              |                              |
    | 1. if (événement == POLLIN)  |              | if (événement == POLLIN)     |
    |    int new_fd = accept(4);   |              |    - read(5, ...);           |
    |                              |              |    - Met dans In-buffer.     |
    | 2. Le ServerManager crée :   |              |    - Requête HTTP entière ?  |
    |    - Un objet Client(new_fd) |              |      -> Prépare Out-buffer.  |
    |    - L'ajoute à sa map.      |              |      -> Demande un POLLOUT   |
    |                              |              |      (Je veux écrire !).     |
    | 3. Le ServerManager ajoute   |              |                              |
    |    new_fd à la liste poll()  |              | if (événement == POLLOUT)    |
    |    pour commencer à          |              |    - write(5, Out-buffer);   |

    |    tour !                    |              |    - Terminé ? -> Close(5)   |
    +------------------------------+              +------------------------------+
             |                                               |
             +-----------------------+-----------------------+

                       (Retour au début de la boucle poll)

3. ZOOM SUR LA MACHINE À ÉTAT D'UN CLIENT (Non-bloquant)
=============================================================================

Parce que le `read()` et le `write()` sont NON BLOQUANTS, ils peuvent s'arrêter
au milieu d'un mot. Le Client doit retenir où il en est !

Étape A : [ READING_STATE ]
          - poll() dit POLLIN.
          - On read() ce qu'on peut. On l'ajoute au "read_buffer".
          - On vérifie : Le buffer contient-il "\r\n\r\n" à la fin ?
            - NON : On retourne attendre dans la boucle.
            - OUI : La requête est complète, on passe à l'Étape B.

Étape B : [ PROCESSING_STATE ]
          - La lecture est finie.
          - On analyse la requête HTTP ("GET /toto.html").
          - On construit la grosse string de réponse ("HTTP/1.1 200 OK...\n\n<html>...").
          - On met cette grosse string dans le "write_buffer".
          - On dit au ServerManager : "Maintenant je n'écoute plus ce client,
            je veux lui PARLER (Changement de POLLIN à POLLOUT sur le FD)".
          - On passe à l'Étape C.

Étape C : [ WRITING_STATE ]
          - poll() dit POLLOUT (Le réseau est prêt à recevoir tes données).
          - On write() TOUT ce qu'on peut du "write_buffer" vers l'OS.
          - write() nous renvoie combien de bytes il a vraiment pu envoyer (ex: 1024).
          - On coupe les 1024 premiers bytes du "write_buffer".
          - Le buffer est-il vide ?
            - NON : Il reste des données pour ce client, on attend un autre POLLOUT.
            - OUI : Réponse finie ! On close(FD), supprime le client des maps.
