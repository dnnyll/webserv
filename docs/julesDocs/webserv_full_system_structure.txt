# SCHÉMA ARCHITECTURE GLOBALE WEBSERV
# (SANS CODE - VUE HÉLICOPTÈRE)

=============================================================================
                       PHASE 1 : LE LANCEMENT (BOOT)
=============================================================================

[ Fichier webserv.conf ] 
       |
       | 1. Lecture et Parsing
       v
+------------------------+
|    ConfigParser        | ---> Produit une liste de configurations de serveurs
| (Machine à état texte) |      (Ex: 3 blocs 'server', dont 2 sur le port 8080)
+------------------------+
       |
       | 2. Instanciation
       v
+------------------------+      [ Liste des Objets Config ]
|    ServerManager       | ---> - Config_Server_1 (Port 80)
|    (Initialisation)    |      - Config_Server_2 (Port 8080)
+------------------------+      - Config_Server_3 (Port 8080, nom 'test.com')
       |
       | 3. Appels Systèmes Réseaux (Création des Sockets d'écoute)
       v
  ===========================================
  | L'OS attribue un FD par Port d'écoute : |
  | (socket -> bind -> fcntl -> listen)     |
  |                                         |
  | FD 3 ---> Écoute le port 80             |
  | FD 4 ---> Écoute le port 8080           |
  ===========================================
  (Note: Serveur 2 et 3 partagent le FD 4)



=============================================================================
             PHASE 2 : LA BOUCLE ASYNCHRONE (LE COEUR DU RÉACTEUR)
=============================================================================

                     +---------------------------------------+
                     | while (true) { poll(tableau_des_FD) } |
                     +---------------------------------------+
                                        |
  +-------------------------------------+-----------------------------------+
  | ÉVÉNEMENT : Quelqu'un frappe à              | ÉVÉNEMENT : Quelqu'un parle sur un
  | la porte (Les Sockets d'écoute)             | FD connu (Les Sockets Clients)
  +-------------------------------------+       +-----------------------------------+
  v                                             v
[ LE MAÎTRE D'HÔTEL (ServerManager) ]         [ LE CLIENT ATTABLÉ (Objet Client) ]
  |                                             |
  | 1. Fait accept() sur FD 3 ou FD 4.          | 1. Fait read() en boucle non-bloquante.
  | 2. Crée par ex: Nouveau FD Client (FD 5)    | 2. Stocke le texte dans "_raw_buffer".
  | 3. Crée un [Objet Client(FD 5)]             | 3. Analyse si "_raw_buffer" = Requête HTTP ?
  | 4. Ajoute FD 5 au tableau poll() avec       |    - NON : Retourne à poll() en POLLIN.
  |    l'intention "POLLIN" (Je veux t'écouter).|    - OUI : Passe à l'étape PARSING.
  v                                             v

==============(La Connexion est établie)===========     ===============(Requête Reçue)==============


=============================================================================
             PHASE 3 : TRAITEMENT ET RÉPONSE (À L'INTÉRIEUR DU CLIENT)
=============================================================================

[ Étape A : LE PARSING ] (Objet: HttpRequest)
  | 1. Découpage du buffer en : Method (GET), URI (/index), Body (Post data).
  | 2. Résolution du serveur VIRTUEL. (Si FD=4, on a deux configurations sur 
  |    8080. On regarde le header "Host: test.com" pour savoir si on utilise
  |    Config_Server_2 ou Config_Server_3).
  v
[ Étape B : LE ROUTING ] (Objet: Server/Location)
  | On utilise la configuration trouvée pour savoir OÙ et COMMENT :
  | - Est-ce un dossier avec un index ? -> read "/var/www/html/index.html"
  | - Est-ce un chemin vers un CGI ? -> Execute le script Python/PHP.
  | - L'URI est-elle interdite ? -> Prépare erreur 403.
  | - Le Body dépasse le max_body_size ? -> Prépare erreur 413.
  v
[ Étape C : LA RÉPONSE ] (Objet: HttpResponse)
  | On a le fichier (ou la réponse du serveur CGI).
  | 1. Construit l'en-tête (HTTP/1.1 200 OK + Content-Length, Content-Type).
  | 2. Concatène le tout dans le "_write_buffer" de l'objet Client.
  | 3. Le Client dit a poll() : "Mon plat est prêt! (Change POLLIN en POLLOUT)".
  v
[ Étape D : L'ENVOI ] (Au prochain tour de poll() qui signal POLLOUT)
  | Fait write(FD 5, _write_buffer).
  | -> Le kernel dit : "J'ai réussi à envoyer 4000 octets" (sur les 2 Mo).
  | -> Le client garde le reste dans son buffer et attend le prochain POLLOUT.
  | -> Quand _write_buffer est vide, on ferme le socket (close(FD 5)). 
  |    Client supprimé !
