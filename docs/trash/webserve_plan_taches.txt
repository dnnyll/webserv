                RÉPARTITION DÉTAILLÉE (ÉQUIPE DE 3 - WEBSERV 42)

================================================================================
PERSONNE 1 — CONFIGURATION / PARSING / VALIDATION
================================================================================

Rôle :
Construire la base du projet : tout ce que le serveur va utiliser comme règles.

--------------------------------------------------------------------------------
1. Parsing du fichier de configuration
--------------------------------------------------------------------------------

- open / read du fichier
- gestion erreurs fichier
- tokenisation :
  - accolades
  - directives
  - blocs server
  - blocs location

- parser syntaxe complète :
  - server { }
  - location { }

--------------------------------------------------------------------------------
2. Structures de données
--------------------------------------------------------------------------------

Implémenter :

- ServerConfig
- LocationConfig
- ResolvedLocation (ou équivalent)

Inclure :

- ports
- server_name
- root
- index
- error_pages
- client_max_body_size
- autoindex
- upload_path
- CGI extensions

--------------------------------------------------------------------------------
3. Validation syntaxique
--------------------------------------------------------------------------------

- directives connues uniquement
- types corrects :
  - int (ports)
  - string (paths)
  - bool (autoindex)
- accolades équilibrées
- valeurs présentes

--------------------------------------------------------------------------------
4. Validation sémantique
--------------------------------------------------------------------------------

- ports valides (1–65535)
- tailles > 0
- méthodes HTTP autorisées
- chemins non vides
- cohérence config globale

--------------------------------------------------------------------------------
5. Résolution des configurations
--------------------------------------------------------------------------------

- inheritance server → location
- création configuration finale utilisable
- préparation du mapping routes

--------------------------------------------------------------------------------
6. Route matching (logique pure)
--------------------------------------------------------------------------------

- implémenter longest prefix match :
  findBestLocation(uri)

- fallback sur "/"

--------------------------------------------------------------------------------
7. Sortie du module
--------------------------------------------------------------------------------

- vector<ServerConfig> propre
- prêt pour réseau

--------------------------------------------------------------------------------
Livrable attendu :
- parser complet fonctionnel
- config validée
- aucune dépendance réseau

================================================================================
PERSONNE 2 — RÉSEAU / EVENT LOOP / CLIENTS
================================================================================

Rôle :
Construire le cœur du serveur non bloquant.

--------------------------------------------------------------------------------
1. Initialisation sockets
--------------------------------------------------------------------------------

- socket()
- setsockopt(SO_REUSEADDR)
- fcntl(O_NONBLOCK)
- bind()
- listen()

- gestion multi ports

--------------------------------------------------------------------------------
2. poll() system
--------------------------------------------------------------------------------

- struct pollfd vector
- ajout :
  - sockets serveurs
  - sockets clients
  - pipes CGI

- boucle principale infinie :
  - poll()
  - dispatch events

--------------------------------------------------------------------------------
3. Acceptation clients
--------------------------------------------------------------------------------

- accept()
- création ClientConnection
- ajout au pollfd

ClientConnection contient :

- fd
- read buffer
- write buffer
- timestamp activité
- état (state machine)
- serveur associé
- requête en cours
- réponse en cours

--------------------------------------------------------------------------------
4. Machine d’état client
--------------------------------------------------------------------------------

Implémenter :

enum ClientState
{
    READING_HEADERS,
    READING_BODY,
    PROCESSING,
    CGI_RUNNING,
    WRITING_RESPONSE,
    CLOSED
};

Transitions :
- lecture → parsing
- parsing → HTTP
- HTTP → CGI ou response
- response → write

--------------------------------------------------------------------------------
5. Gestion lecture réseau
--------------------------------------------------------------------------------

- recv() non bloquant
- accumulation buffer
- parsing progressif
- gestion fragmentation HTTP

Cas critiques :
- requête coupée
- requête multiple dans buffer
- client lent

--------------------------------------------------------------------------------
6. Gestion écriture réseau
--------------------------------------------------------------------------------

- send() partiel obligatoire
- gestion offset buffer
- retry via poll()

--------------------------------------------------------------------------------
7. Timeout clients
--------------------------------------------------------------------------------

- lastActivity timestamp
- suppression client si timeout
  (30–60s)

anti :
- slowloris
- clients bloqués

--------------------------------------------------------------------------------
8. Nettoyage ressources
--------------------------------------------------------------------------------

- fermeture fd
- suppression pollfd
- suppression client
- gestion erreurs recv/send/poll

--------------------------------------------------------------------------------
9. Intégration CGI (niveau transport)
--------------------------------------------------------------------------------

- ajout pipes dans poll
- gestion fd CGI
- communication async

--------------------------------------------------------------------------------
Livrable attendu :
- serveur multi-client fonctionnel
- non bloquant réel
- stable sous charge simple

================================================================================
PERSONNE 3 — HTTP / CGI / RESPONSE LOGIC
================================================================================

Rôle :
Transformer une requête en réponse complète conforme HTTP.

--------------------------------------------------------------------------------
1. Parsing HTTP
--------------------------------------------------------------------------------

Créer :

HttpRequest parser

Contenu :

- method
- uri
- http version
- headers map
- body

--------------------------------------------------------------------------------
2. Parsing incrémental HTTP
--------------------------------------------------------------------------------

IMPORTANT :

- détecter \r\n\r\n
- gérer fragmentation recv()
- Content-Length obligatoire
- support chunked (si possible)

--------------------------------------------------------------------------------
3. Sélection serveur virtuel
--------------------------------------------------------------------------------

- lecture header Host
- matching server_name
- fallback default server

--------------------------------------------------------------------------------
4. Résolution route
--------------------------------------------------------------------------------

- utiliser findBestLocation()
- fusion Server + Location → ResolvedLocation

--------------------------------------------------------------------------------
5. Traitement HTTP methods
--------------------------------------------------------------------------------

GET :
- path resolution
- file read
- directory handling
- autoindex
- index file

POST :
- write upload file
- validation body size

DELETE :
- unlink file
- sécurité root

--------------------------------------------------------------------------------
6. Sécurité fichiers
--------------------------------------------------------------------------------

CRITIQUE :

- normalisation path
- empêcher ../ traversal
- restriction root directory

--------------------------------------------------------------------------------
7. Autoindex
--------------------------------------------------------------------------------

- génération HTML
- listing fichiers
- liens accessibles

--------------------------------------------------------------------------------
8. MIME types
--------------------------------------------------------------------------------

table de mapping :

.html → text/html
.css → text/css
.jpg → image/jpeg
.png → image/png
.js → application/javascript

--------------------------------------------------------------------------------
9. Construction réponse HTTP
--------------------------------------------------------------------------------

HttpResponse builder :

- status line
- headers :
  - Content-Length
  - Content-Type
  - Date
  - Server
- body

--------------------------------------------------------------------------------
10. CGI (logique complète)
--------------------------------------------------------------------------------

- détection extension CGI
- fork()
- pipe()
- dup2()
- execve()

--------------------------------------------------------------------------------
CGI async :

- stdin pipe write
- stdout pipe read
- intégration poll()

--------------------------------------------------------------------------------
11. Timeout CGI
--------------------------------------------------------------------------------

- kill process si trop long
- éviter blocage serveur

--------------------------------------------------------------------------------
12. waitpid cleanup
--------------------------------------------------------------------------------

- éviter zombies
- WNOHANG

--------------------------------------------------------------------------------
Livrable attendu :
- HTTP complet fonctionnel
- CGI opérationnel
- réponses conformes RFC basique
