WEBSERV EDGE CASE TEST SUITE
════════════════════════════════════════════════════════════════

--------------------------------------------------------------
[1] LF-only line endings (no CR) — many parsers assume CRLF
--------------------------------------------------------------
printf 'GET / HTTP/1.1\nHost: localhost\n\n' | nc localhost 8080

EXPECTED: Either accepted (lenient) or 400 Bad Request.
Should NOT hang waiting for a CR that never comes, and should
NOT crash/segfault.

--------------------------------------------------------------
[2] Content-Length AND Transfer-Encoding both present (smuggling vector)
--------------------------------------------------------------
printf 'POST / HTTP/1.1\r\nHost: localhost\r\nContent-Length: 5\r\nTransfer-Encoding: chunked\r\n\r\n0\r\n\r\n' | nc localhost 8080

EXPECTED: 400 Bad Request. RFC 7230 §3.3.3 says Transfer-Encoding
takes priority and the message should be rejected as ambiguous
(this is literally the HTTP request-smuggling bug class).

--------------------------------------------------------------
[3] Chunked body with a 0-size chunk that ISN'T the terminator
    (extension after size, garbage chunk-size hex)
--------------------------------------------------------------
printf 'POST / HTTP/1.1\r\nHost: localhost\r\nTransfer-Encoding: chunked\r\n\r\n4;foo=bar\r\nWiki\r\n0\r\n\r\n' | nc localhost 8080

EXPECTED: 200, body = "Wiki". Chunk extensions after ';' must be
ignored, not parsed as part of the size or cause an error.

--------------------------------------------------------------
[4] Chunk size given in hex but larger than actual bytes sent
--------------------------------------------------------------
printf 'POST / HTTP/1.1\r\nHost: localhost\r\nTransfer-Encoding: chunked\r\n\r\nFFFFFFFF\r\nWiki\r\n0\r\n\r\n' | nc -q1 localhost 8080

EXPECTED: Server should NOT allocate 4GB or hang forever waiting
for more bytes. Should time out or 400 gracefully.

--------------------------------------------------------------
[5] Negative / malformed Content-Length
--------------------------------------------------------------
printf 'POST / HTTP/1.1\r\nHost: localhost\r\nContent-Length: -10\r\n\r\nhello' | nc localhost 8080

EXPECTED: 400 Bad Request (must not cast to size_t and read
"18446744073709551606" bytes, and must not crash on strtol).

--------------------------------------------------------------
[6] Content-Length with leading zeros / whitespace / non-digit garbage
--------------------------------------------------------------
printf 'POST / HTTP/1.1\r\nHost: localhost\r\nContent-Length: 007\r\n\r\n1234567' | nc localhost 8080
printf 'POST / HTTP/1.1\r\nHost: localhost\r\nContent-Length: 5 \r\n\r\nhello' | nc localhost 8080
printf 'POST / HTTP/1.1\r\nHost: localhost\r\nContent-Length: 5a\r\n\r\nhello' | nc localhost 8080

EXPECTED: First two are technically valid → 200 with 7-byte read
of "007". Third ("5a") is invalid → 400.

--------------------------------------------------------------
[7] Two Content-Length headers with different values
--------------------------------------------------------------
printf 'POST / HTTP/1.1\r\nHost: localhost\r\nContent-Length: 5\r\nContent-Length: 10\r\n\r\nhelloworld' | nc localhost 8080

EXPECTED: 400 Bad Request. Duplicate conflicting Content-Length
is a classic smuggling trick — must be rejected outright, not
"take the first" or "take the last" silently.

--------------------------------------------------------------
[8] Request line with absurdly long URI (buffer overflow bait)
--------------------------------------------------------------
python3 -c "print('GET /' + 'A'*100000 + ' HTTP/1.1\r\nHost: localhost\r\n\r\n', end='')" | nc localhost 8080

EXPECTED: 414 URI Too Long (or 400). Must not crash, must not
allocate unbounded memory silently.

--------------------------------------------------------------
[9] Header line with no space after colon, or space before colon
--------------------------------------------------------------
printf 'GET / HTTP/1.1\r\nHost:localhost\r\n\r\n' | nc localhost 8080
printf 'GET / HTTP/1.1\r\nHost : localhost\r\n\r\n' | nc localhost 8080

EXPECTED: "Host:localhost" (no space) → valid, 200.
"Host : localhost" (space before colon) → 400 per RFC 7230 §3.2.4,
this is explicitly called out as a request-smuggling vector and
MUST be rejected, not trimmed-and-accepted.

--------------------------------------------------------------
[10] Missing Host header on HTTP/1.1
--------------------------------------------------------------
printf 'GET / HTTP/1.1\r\n\r\n' | nc localhost 8080

EXPECTED: 400 Bad Request. Host is mandatory in HTTP/1.1.

--------------------------------------------------------------
[11] Two Host headers
--------------------------------------------------------------
printf 'GET / HTTP/1.1\r\nHost: localhost\r\nHost: evil.com\r\n\r\n' | nc localhost 8080

EXPECTED: 400 Bad Request.

--------------------------------------------------------------
[12] Method is lowercase / mixed case
--------------------------------------------------------------
printf 'get / HTTP/1.1\r\nHost: localhost\r\n\r\n' | nc localhost 8080

EXPECTED: 400 or 501 — HTTP methods are case-sensitive tokens,
"get" is not "GET".

--------------------------------------------------------------
[13] Bare LF inside headers mixed with CRLF request line (mixed line endings)
--------------------------------------------------------------
printf 'GET / HTTP/1.1\r\nHost: localhost\nX-Test: 1\r\n\r\n' | nc localhost 8080

EXPECTED: Reject or handle consistently — pick one policy and
don't silently mis-split headers (this breaks a lot of naive
strstr("\r\n\r\n") parsers when a lone \n sneaks in mid-header).

--------------------------------------------------------------
[14] Request with NO final empty line — client sends headers then
     just... stops (partial request, socket stays open)
--------------------------------------------------------------
printf 'GET / HTTP/1.1\r\nHost: localhost\r\n' | nc -q3 localhost 8080

EXPECTED: Server waits, then times out and closes the connection
(or sends 408 Request Timeout). Must NOT hang the whole event
loop / block other clients (this is THE classic single-threaded
select()/poll() webserv bug).

--------------------------------------------------------------
[15] Pipelined requests in one packet (2 GETs sent together)
--------------------------------------------------------------
printf 'GET / HTTP/1.1\r\nHost: localhost\r\n\r\nGET /favicon.ico HTTP/1.1\r\nHost: localhost\r\n\r\n' | nc -q1 localhost 8080

EXPECTED: TWO responses, in order, on the same connection. Must
not treat the second request as part of the first request's body,
and must not drop it.

--------------------------------------------------------------
[16] Expect: 100-continue
--------------------------------------------------------------
printf 'POST /upload HTTP/1.1\r\nHost: localhost\r\nContent-Length: 5\r\nExpect: 100-continue\r\n\r\nhello' | nc -q1 localhost 8080

EXPECTED: Either "100 Continue" then final response, or just the
final response outright — but must not hang waiting forever for
a continuation that the client already sent.

--------------------------------------------------------------
[17] Percent-encoded path traversal / null byte in URI
--------------------------------------------------------------
printf 'GET /..%2f..%2f..%2fetc%2fpasswd HTTP/1.1\r\nHost: localhost\r\n\r\n' | nc localhost 8080
printf 'GET /index.html%00.php HTTP/1.1\r\nHost: localhost\r\n\r\n' | nc localhost 8080

EXPECTED: 400/403/404 — never serve a file outside the configured
root. Decode %2f BEFORE or carefully around traversal checks, and
reject/strip embedded null bytes rather than truncating C-strings
unsafely.

--------------------------------------------------------------
[18] Double slashes / trailing slash on a CGI or static route
--------------------------------------------------------------
printf 'GET //index.html HTTP/1.1\r\nHost: localhost\r\n\r\n' | nc localhost 8080
printf 'GET /directory HTTP/1.1\r\nHost: localhost\r\n\r\n' | nc localhost 8080
(no trailing slash, but /directory/ is a configured location)

EXPECTED: consistent behavior — either normalize // to /, and
either 301-redirect /directory -> /directory/ or serve it
directly, but pick one and be consistent everywhere (routes,
CGI, autoindex).

--------------------------------------------------------------
[19] HTTP/0.9-style request (no version, no headers at all)
--------------------------------------------------------------
printf 'GET /\r\n\r\n' | nc localhost 8080

EXPECTED: 400 Bad Request (webserv 42 doesn't need to support 0.9,
but must not crash trying to parse "HTTP/0.9" out of nothing).

--------------------------------------------------------------
[20] Connection: keep-alive vs close mismatch across versions
--------------------------------------------------------------
printf 'GET / HTTP/1.0\r\nHost: localhost\r\nConnection: keep-alive\r\n\r\n' | nc -q2 localhost 8080
printf 'GET / HTTP/1.1\r\nHost: localhost\r\nConnection: close\r\n\r\n' | nc -q2 localhost 8080

EXPECTED: HTTP/1.0 + "Connection: keep-alive" → connection stays
open (opt-in). HTTP/1.1 + "Connection: close" → connection closes
after response (opt-out). Default for 1.0 is close, default for
1.1 is keep-alive — verify both defaults too by omitting the header.

--------------------------------------------------------------
[21] Slow-loris: send request one byte at a time with delays
--------------------------------------------------------------
(python3)
import socket,time
s=socket.socket(); s.connect(("localhost",8080))
for c in "GET / HTTP/1.1\r\nHost: localhost\r\n\r\n":
    s.send(c.encode()); time.sleep(1)
print(s.recv(4096))

EXPECTED: Server must still be responsive to OTHER clients while
this one trickles in — proves your select()/poll()/epoll loop
isn't blocking on a single slow read().
